## 四、关键决策与坑点

### 决策 1：`packages/ai` 改为 CommonJS + dist 构建
**问题**：ai 原本是 `type:module` + `main:src/index.ts`（TS 源），与 shared 一样会阻塞 server runtime 加载。
**处理**：ai 是我的 owned 目录，直接改为 CommonJS + `main:./dist/index.js`，与 shared D007 修复对齐。
**教训**：被 Node runtime 直接 require 的 workspace 包必须有编译产物，不能暴露 TS 源。

### 决策 2：server `tsconfig.json` 用 CommonJS/Node10
**问题**：NestJS 脚手架默认 `nodenext` 与 shared 的扩展名省略 import 冲突，typecheck 期报 `Relative import paths need explicit file extensions`。
**处理**：server tsconfig 切回 `module:CommonJS, moduleResolution:Node10`。runtime 加载靠 shared/ai 的 dist，不受影响。

### 决策 3：JWT `expiresIn` 用秒数
**问题**：`@nestjs/jwt` v11 的 `expiresIn?: StringValue | number`（`ms` 库的 branded type），传字符串 `'7d'` 类型不匹配。
**处理**：写 `parseDurationToSeconds()` 把 `'7d'` 解析为 `604800`（number），`getJwtExpiresInSeconds()` 返回 number。

### 决策 4：`import type` 分离
**问题**：`isolatedModules + emitDecoratorMetadata` 要求装饰器签名涉及的类型用 `import type` 导入，否则 re-export 报错。
**处理**：`app.controller.ts` 拆分 `import { AppService }` + `import type { HealthCheckResult }`。

### 决策 5：`start:dev` 前缀构建 shared + ai
**问题**：shared/ai 改为 dist 输出后，开发期源码变更需重新构建才生效。
**处理**：`start:dev` = `pnpm --filter @bomi/shared build && pnpm --filter @bomi/ai build && nest start --watch`。

## 六、向整合方的提案（待处理）

### 提案 1：shared `moduleResolution=node10` deprecated warning
**现象**：`pnpm --filter @bomi/shared build` 输出 `TS5107: Option 'moduleResolution=node10' is deprecated and will stop functioning in TypeScript 7.0`，但 dist 仍正常生成。
**影响**：当前可用，但 TS 7.0 升级时会阻塞。
**建议**：整合方在 shared `tsconfig.json` 加 `"ignoreDeprecations": "6.0"`，或迁移到 `moduleResolution: "node16"`/`"nodenext"`（需同步补全内部 import 的 `.js` 扩展名）。
**状态**：shared 在我黑名单内，仅提案，不自行修改。
